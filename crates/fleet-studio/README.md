# Fleet Studio

Katala Tune の保存済みの機体分析と最近の作業を、読み取り専用で見る GPUI の試験的な入口です。既存の Tauri アプリや `tune` CLI はそのまま使えます。

## ビルドと起動

Rust 1.99.0 と GPUI 0.2.2 を使用します。GPUI は `=0.2.2` に固定し、このディレクトリの `Cargo.lock` で依存関係を固定しています。更新時は別 branch でバージョンと lockfile を更新し、Windows と macOS のビルド・起動・操作を再検証してください。GPUI の依存関係は、既存の Tauri アプリの lockfile と分離しています。

Windows の例（PowerShell、リポジトリのルートから）:

```powershell
$env:CARGO_TARGET_DIR = "$PWD/target/fleet-studio"
$env:CARGO_PROFILE_DEV_DEBUG = '0'
cargo build --manifest-path crates/fleet-studio/Cargo.toml --features gui --locked -j 1
& "$env:CARGO_TARGET_DIR/debug/fleet-studio.exe"
```

Windows で Rust コンパイラ自体が内部エラーやアクセス違反で終了する場合は、既存の生成物を消さず、別の `CARGO_TARGET_DIR` を指定して `CARGO_INCREMENTAL=0` で再実行できます。これは切り分け手段であり、コンパイラ障害の根本修正ではありません。

macOS の例:

```sh
cargo run --manifest-path crates/fleet-studio/Cargo.toml --features gui --locked -j 1
```

macOS の既定ビルドは、GPUI 0.2.2 のシェーダーを事前コンパイルするために `xcrun metal` と `xcrun metallib` が必要です。Command Line Tools の有無だけでは、これらを利用できるかは判断できません。この版の macOS ビルドと画面は未検証です。Windows では旧版のサンプルをビルド・起動して操作を確認しています。score の取得範囲の注記を含む現在の版は、ビルド・起動とも未確認です。

`--features 'gui,gpui/runtime_shaders'` はシェーダーを実行時にコンパイルする未検証の代替候補です。この指定でも Metal 自体、bindgen が利用できる libclang、SDK などは引き続き必要です。Windows 向けの依存 feature 解決では指定の反映を確認していますが、macOS 向けの依存解決・ビルド・起動、起動時コンパイルの成否や性能への影響は未確認です。

サンプルを明示して試す場合は、Windows では実行ファイルに `--sample` を追加します。`cargo run` では `-- --sample` を追加します。サンプル画面にはその旨を表示し、台帳・DB の読取や LLM 接続を行いません。サンプルの追加先は確認・許可・取消の表示だけで、許可しても通信せず、更新するとサンプルの許可は消えます。サンプルのリポジトリ・場所・PR・監査先は実際には開きません。説明と Issue は実際のリンクです。

保存済みの機体要約を起動時から表示する場合は、操作者が閲覧権限と適用ルールを確認したうえで、台帳 ID ごとに `--saved-summary=<ID>` を指定できます。複数指定できます。たとえば `cargo run` では `-- --saved-summary=<ID>` を追加します。この指定は設定に保存されず、この起動中の読み取り専用の許可になります。初回の台帳照合時に、指定 ID・台帳行のいずれかを一意に確認できない場合は、どの指定機体も自動表示しません。初回の照合結果を受け取る時点で起動から5秒以上経っていれば、タイマー通知の順序にかかわらず起動時の指定を取り消します。許可後の保存要約の読取が5秒を超えた場合は、終了待ち・不明と表示し、完了後に表示する場合があります。初回照合後に台帳行が変わった機体は許可を取り消します。変わっていない他の指定機体は表示される場合があり、読み取り中の変更では全件を非表示にする場合もあります。表示中の画面からも許可を取り消せます。更新時は許可中の保存要約を読み直しますが、SSH 接続やリモート実行はしません。すでに開始した読み取りの停止は保証しません。ID はプロセスの引数としてローカルの他の利用者に見える場合があります。会社管理・共有環境では利用前に権限とルールを確認してください。`--sample` と併用した場合は指定を無視し、実データを読みません。

**確認画面:** 機体の保存要約を画面から個別に選ぶ場合と非ループバック LLM の個別許可は、対象・取得範囲・再取得・取消の限界・会社管理の権限確認を独立したスクロール画面に示します。本文の末尾が描画された後に限り許可操作を受け付けます。スクロール到達は内容を読んだ証明ではありません。画面が 320×200 論理 px 未満、横へのはみ出しが 1 論理 px を超える、描画状況が不明、対象や画面が変わった場合は許可できません。サイズ変更では確認を中止し、対象を選び直します。検索の IME 変換中は確認を開始できず、先に変換を確定または取り消します。旧確認で押した Y を保持したまま新しい確認に移った場合、解放後に回復用の押下・解放を経てから確認します。OS 側の IME・focus 通知順は未検証です。GPUI の文字 shaping 失敗や欠字は scroll bounds だけでは検出できません。対象や範囲を読めない場合は許可せず中止してください。今回の確認画面は Windows・macOS とも実画面の操作・描画が未検証です。GPUI の描画後 callback が届かない場合は許可できないまま待機します。ループバック先の自動照会、明示された --recent-local と --saved-summary は別の経路です。

最近の作業は既定で非表示です。操作者がこの機体を個人・非共有と確認し、会社管理の場合は適用ルールと権限も確認した後に限り、起動時に `--recent-local` を明示すると、この機体の保存済み情報を表示できます。遠隔機の最近の作業は現在は対象外です。この指定は設定に保存しません。

## データの出どころ

- 機体台帳は Katala Tune の `nodes.json`、保存要約は同じアプリの既存 DB を使います。`KATALA_TUNE_CONFIG` と `KATALA_TUNE_DATA_DIR` の既存指定も使えます。起動時は台帳上の機体・役割・運用状態を表示し、`--saved-summary` を明示した機体だけ保存要約の読み取りを申請します。省略した機体は未許可です。許可が 0 件なら機体要約のために DB を開きません。別途 `--recent-local` を指定した場合の最近の作業は独立した読取です。
- 機体カードから個別の確認画面を開き、その台帳 ID に保存された情報へのアクセス権と適用ルールを確認できます。サンプルは模擬であり、保存 DB を読みません。許可はこの起動中だけ、その ID の保存要約に限ります。 許可中は R 等の更新時に同じ ID の要約を再読取し、カードからいつでも取消できます。 この許可は最近の作業・LLM・監査の許可ではなく、カード操作ではそれらを起動しません。role、共有属性、hostname や過去の収集履歴は権限の証明ではありません。共有機も個別の確認対象にできます。重複 ID、不正な ID、対象を照合できない台帳行は表示を許可できません。機体を接続・起動する操作は行いません。
- 要約 SQL は許可された ID を指定し、記録時刻・score・重大／注意件数と失敗の有無・鮮度設定だけを返します。snapshot の `data` 本文や GPU・process の履歴、失敗本文は返しません。記録は台帳 ID に紐づく過去情報であり、過去に同じ ID を使っていた物理機体や来歴、本文の完全性、現在の接続・正常性は確認できません。時刻・失敗・設定の欠損や破損は不明として扱います。 score と重大・警告件数が対象とした情報の取得範囲はこの画面では検証しておらず、各項目の取得失敗・非該当も判別しない。小さい画面での折返しは未検証。
- 表示許可はカードから取り消せます。表示値は直ちに消し、古い更新結果は採用しません。更新時の台帳再照合中も、既存の時刻・数値・取得状態を画面上は伏せます。既に始まった DB 読取は遡って取り消せないため、worker の終了までは「取消処理中」と表示してその ID の再許可を止めます。待機時間の上限や強制終了は保証しません。DB 一時障害時に限り、同じ許可と台帳照合を維持できた前回値を元の時刻と読取失敗を添えて表示します。許可取消、台帳の読取失敗、対象の変更・重複時には残しません。台帳照合後の変更は次の更新まで自動反映されず、照合と DB 読取の間の同時変更を原子的に防ぐ保証はありません。
- DB は `Store::open_read_only` で開き、DB の作成・スキーマ移行を行いません。ただし SQLite の WAL モードでは条件により `-wal` / `-shm` ファイルが作成され得ます。未反映の WAL を見落とし得る `immutable` は指定しません。
- 要約記録時刻の鮮度は、Katala Tune と同じ優先順（DB の設定、台帳、既定値）による `probe_minutes` の 3 倍を基準にします。設定の破損や読み取り失敗では鮮度を不明とします。LLM 一覧は 5 分、衛生監査は 1 時間を超えると古いと表示し、画面を開いたままでも 30 秒ごとに期限を再判定します。
- 「最近の作業」は同じ DB の保存済み AI セッションと、機体 ID で絞った収集状態だけを単一の読み取りトランザクションで取得します。専用 SQL は対象機だけのツール・作業場所・活動時刻・長さ制限付き PR 情報と状態の旗のみを返し、セッション ID・ファイル名・収集エラー本文は返しません。会話ファイル・会話本文は開かず、新しい収集や他の機体への接続は行いません。`shared: true`、不正な `shared`、`ai_sessions: false`、不正・重複 ID は除外します。`shared` 未記入は台帳上は不明と表示し、操作者が非共有を確認したうえで上記の明示指定を行ったときに限り、この機体を対象にします。hostname の `.local` 表記を正規化して照合し、複数行が一致するときは共有・停止中を含めて曖昧と判定します。保存 DB の機体 ID は接続先の本人確認ではありません。
- 最近の作業では、親セッションのみを対象に、最終活動時刻と、収集の最終試行・最終成功・失敗・続き・一部失敗を分けます。最終成功の古さは設定された `ai_minutes` の 3 倍（DB の設定、台帳、既定 30 分の順）で判定し、設定が破損していれば不明とします。活動時刻を現在の稼働状態とは扱いません。この機体の新しい順で最大 20 件です。検索はこの表示範囲の機体名・ツール・作業場所のみで、表示外や古いセッションの網羅検索ではありません。
- 収集状態が不明・失敗・部分的な場合はその旨を示します。これは Katala Tune が保存した取込上の記録であり、既存の収集元には完了条件を厳密に復元できないケースがあるため、正常完了や網羅性は保証しません。`truncated` は続きまたは拒否区間の再読込待ちを示します。部分失敗は保存時に先頭 5 件までに制限されるため、5 件の場合は「5 件以上」と示します。部分失敗情報の欠損・破損・上限超過は不明です。PR は空・不明・一部未確認を区別します。
- 更新開始時には以前の最近の作業を消し、台帳の読み取り失敗や取得中の対象変更では再表示しません。台帳の照合時刻を表示しますが、その後の設定変更は自動反映されません。`R` で更新してください。最近の作業のリンク操作時には、準備の前と OS への引き渡し直前の両方で台帳と表示世代を再照合し、更新前の操作や対象が変わった操作は開きません。最終照合と OS 操作の短い間に生じる同時変更を原子的に防ぐ保証はなく、引き渡し済みの OS 操作は取り消せません。読み込みが 5 秒を超えた場合は待機中と表示し、重複処理を起こさず完了後に最新の更新要求をやり直します（元の DB 読み込みを強制終了する保証はありません）。
- 作業場所は、この機体の絶対パスまたは `~` の展開後も UNC でないパスだけをローカル候補とし、遠隔パスは開きません。PR は認証情報・query・fragment のない正規の GitHub PR URL のみ最大 3 件を確認します。Windows では作業場所と確認済み PR を開けます。セッションの自動再開コマンドは実行しません。
- `この機体を監査` は明示操作時のみ既存 `tune-core::hygiene` を使い、正規化した hostname が台帳の一行にだけ一致するこの機体を読み取ります。共有設定が `true` または不正な型の機体は除外し、未記入は不明として表示します。遠隔監査は、機体ごとの権限と実際の接続先 hostname を確認できないため未対応で、SSH 接続もしません。 R を受け付けた時点で前回の監査結果とリンク許可を破棄し、再監査は自動実行しません。進行中の監査自体は停止を保証せず、終了後の旧結果は表示しません。監査完了後に同じ対象行を再照合し、監査先を開く操作でも準備前と OS 引き渡し直前に台帳を再読込して対象・一意性・取消を確認します。台帳への外部変更は R なしでは自動検知しないため、表示は次の更新まで古い場合があります。最終照合と OS 引き渡しの間は原子的ではなく、開始済みの OS 操作を遡って止めることはできません。会社管理の場合は操作者が適用ルールと権限を確認してください。監査には時間・件数の上限があり、失敗・打ち切り・未観測を表示します。探索先・子ディレクトリ・`.git` の属性や一覧を確認できない場合は、確認できた結果を残して未確認とし、例外本文や失敗した子のパスは追加しません。発見後の属性確認に失敗した行も未観測にします。OS が拒否を不存在と返す場合や同じ名前の対象が走査中に置換される競合は区別できない場合があります。属性の取得が停止した場合の時間上限も保証しません。Windows の実 junction と macOS は今回の修正について未検証です。読み取りが EOF に達していなければ途中出力を正常扱いしませんが、その後も reader スレッドが残る場合があり、全体の時間上限や子孫の回収は保証できません。監査の網羅性は不明です。Git の ahead / behind は最後の fetch 時点の追跡参照との差で、現在の remote とは限りません。fetch、リポジトリの変更、モデルの推論は行いません。
- ローカルの Strata `127.0.0.1:18080`、Ollama `127.0.0.1:11434`、LM Studio `127.0.0.1:1234` と、明示設定されたループバック先には、起動時と更新時にモデル一覧の GET だけを送ります。各応答には 2 秒・256 KiB の上限を設けています。サーバーに届かない場合は不明／タイムアウトであり、停止を断定しません。以前の成功と今回の失敗は別の時刻で示します。
- 追加先は、実行時の `FLEET_STUDIO_LLM_ENDPOINTS` に `表示名|IP:ポート|openai` または `表示名|IP:ポート|ollama` の形式で指定します。複数はセミコロンで区切り、先頭 8 件までを検査します。名前解決は行わず、ループバック・プライベートネットワーク・共有アドレス帯の IP のみ受け付けます。不正な指定と重複は区別して件数を表示します。設定は保存しません。
- 非ループバックの追加先は既定では「未照会」で、起動時や通常更新では接続しません。サンプルでは確認・許可を通信なしで模擬できます。アドレス・ポート・プロトコルと平文 HTTP であることを個別に確認して許可した先だけ、有効化時とこの起動中の R 更新のたびにモデル一覧を取得します。許可は表示名を含む接続先の識別情報に結び付き、変更された設定には引き継ぎません。更新の受付時に確認中の内容を無効にし、更新待ちの間は新しい確認を始められません。更新前の照会結果は採用せず、完了後に再照会します。保持済みの値は更新待ち・前回と表示します。表示中の行の「許可を取り消す」は更新待ちの間も利用でき、取消後に前回の値を直ちに消します。対象が隠れている場合は先に検索を解除します。未開始の通信を阻止できたか、開始が確定して取り消せない場合があるかを表示します。未照会・失敗・古い結果は区別し、推論やモデルの変更は行いません。会社管理か個人かは推定しません。
- Windows では `L` で表示中の追加先を選び、上下キーで移動、Enter で接続内容を確認し、末尾に移動後、別の `Y` で有効化できます。許可済みの選択先は `X` で取り消し、Esc で確認と選択を中止します。ループバックと検索で隠れた行は選べません。状態の変化で行が隠れた場合は、検索を解除して対象を選び直してください。更新待ちの間も既存許可は取り消せます。検索・IME を優先し、修飾キーや長押しを許可・取消に使いません。選択とキー gate の一部は純粋な状態テストとコード確認で検証しています。GUI では下記のサンプル基本操作だけを確認し、権限確認・許可・取消は未検証です。
- フォーカス復帰後は、Windows では `L`・`M`、Windows 以外では `M` で対象の選択を始められ、`/` で検索を開始できます。上下や許可・取消などのキーは、解放を確認できるまで押下を受け付けず、必要に応じて押し直しを案内します。検索中の Enter・Esc やフォーカス喪失による終了は、サンプル以外では既存の非同期検索処理へ進みます。現状の `search_topology` は未対応を返して DB を読みません。文字の長押し・IME・focus の短い離脱や OS のイベント順は合成試験だけでは保証できません。
