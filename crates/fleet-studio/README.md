# Fleet Studio

Katala Tune の保存済みの機体分析と最近の作業を、読み取り専用で見る GPUI の試験的な入口です。既存の Tauri アプリや `tune` CLI はそのまま使えます。

## ビルドと起動

Rust 1.99.0 と GPUI 0.2.2 を使用します。GPUI は `=0.2.2` に固定し、このディレクトリの `Cargo.lock` で依存関係を固定しています。更新時は別 branch でバージョンと lockfile を更新し、Windows と macOS のビルド・起動・操作を再検証してください。GPUI の依存関係は、既存の Tauri アプリの lockfile と分離しています。

Windows の例（PowerShell、リポジトリのルートから）:

```powershell
$env:CARGO_TARGET_DIR = "$PWD/target/fleet-studio"
$env:CARGO_PROFILE_DEV_DEBUG = '0'
cargo build --manifest-path crates/fleet-studio/Cargo.toml --features gui --locked -j 1
& "$env:CARGO_TARGET_DIR/debug/fleet-studio.exe"
```

Windows で Rust コンパイラ自体が内部エラーやアクセス違反で終了する場合は、既存の生成物を消さず、別の `CARGO_TARGET_DIR` を指定して `CARGO_INCREMENTAL=0` で再実行できます。これは切り分け手段であり、コンパイラ障害の根本修正ではありません。

macOS の例:

```sh
cargo run --manifest-path crates/fleet-studio/Cargo.toml --features gui --locked -j 1
```

macOS はフル Xcode と Metal コンパイラが必要です。Command Line Tools の存在だけでは足りません。この版の macOS ビルドと画面は未検証です。Windows のネイティブ画面でビルド・起動を確認しています。

サンプルを明示して試す場合は、Windows では実行ファイルに `--sample` を追加します。`cargo run` では `-- --sample` を追加します。サンプル画面にはその旨を表示し、台帳・DB の読取や LLM 接続を行いません。サンプルのリポジトリ・場所・PR・監査先は実際には開きません。説明と Issue は実際のリンクです。

最近の作業は既定で非表示です。操作者がこの機体を個人・非共有と確認し、会社管理の場合は適用ルールと権限も確認した後に限り、起動時に `--recent-local` を明示すると、この機体の保存済み情報を表示できます。遠隔機の最近の作業は現在は対象外です。この指定は設定に保存しません。

## データの出どころ

- 機体台帳は Katala Tune の `nodes.json`、分析は同じアプリの既存 DB を使います。`KATALA_TUNE_CONFIG` と `KATALA_TUNE_DATA_DIR` の既存指定も使えます。DB は `Store::open_read_only` で開き、作成・移行しません。保存済みの最終成功時刻と最新の失敗を分けて表示します。これは現在の SSH 接続結果ではありません。
- 分析の鮮度は、Katala Tune と同じ優先順（DB の設定、台帳、既定値）による `probe_minutes` の 3 倍を基準にします。設定の破損や読み取り失敗では鮮度を不明とします。LLM 一覧は 5 分、衛生監査は 1 時間を超えると古いと表示し、画面を開いたままでも 30 秒ごとに期限を再判定します。失敗や時刻不明は正常と扱わず、取得失敗時は前回の値と時刻を区別して残します。
- 「最近の作業」は同じ DB の保存済み AI セッションと、機体 ID で絞った収集状態だけを単一の読み取りトランザクションで取得します。専用 SQL は対象機だけのツール・作業場所・活動時刻・長さ制限付き PR 情報と状態の旗のみを返し、セッション ID・ファイル名・収集エラー本文は返しません。会話ファイル・会話本文は開かず、新しい収集や他の機体への接続は行いません。`shared: true`、不正な `shared`、`ai_sessions: false`、不正・重複 ID は除外します。`shared` 未記入は台帳上は不明と表示し、操作者が非共有を確認したうえで上記の明示指定を行ったときに限り、この機体を対象にします。hostname の `.local` 表記を正規化して照合し、複数行が一致するときは共有・停止中を含めて曖昧と判定します。保存 DB の機体 ID は接続先の本人確認ではありません。
- 最近の作業では、親セッションのみを対象に、最終活動時刻と、収集の最終試行・最終成功・失敗・続き・一部失敗を分けます。最終成功の古さは設定された `ai_minutes` の 3 倍（DB の設定、台帳、既定 30 分の順）で判定し、設定が破損していれば不明とします。活動時刻を現在の稼働状態とは扱いません。この機体の新しい順で最大 20 件です。検索はこの表示範囲の機体名・ツール・作業場所のみで、表示外や古いセッションの網羅検索ではありません。
- 収集状態が不明・失敗・部分的な場合はその旨を示します。これは Katala Tune が保存した取込上の記録であり、既存の収集元には完了条件を厳密に復元できないケースがあるため、正常完了や網羅性は保証しません。`truncated` は続きまたは拒否区間の再読込待ちを示します。部分失敗は保存時に先頭 5 件までに制限されるため、5 件の場合は「5 件以上」と示します。部分失敗情報の欠損・破損・上限超過は不明です。PR は空・不明・一部未確認を区別します。
- 更新開始時には以前の最近の作業を消し、台帳の読み取り失敗や取得中の対象変更では再表示しません。台帳の照合時刻を表示しますが、その後の設定変更は自動反映されません。`R` で更新してください。最近の作業のリンク操作時には、準備の前と OS への引き渡し直前の両方で台帳を再照合し、対象が変わっていれば開きません。最終照合と OS 操作の短い間に生じる同時変更を原子的に防ぐ保証はありません。読み込みが 5 秒を超えた場合は待機中と表示し、重複処理を起こさず完了後に最新の更新要求をやり直します（元の DB 読み込みを強制終了する保証はありません）。
- 作業場所は、この機体の絶対パスまたは `~` の展開後も UNC でないパスだけをローカル候補とし、遠隔パスは開きません。PR は認証情報・query・fragment のない正規の GitHub PR URL のみ最大 3 件を確認します。Windows では作業場所と確認済み PR を開けます。セッションの自動再開コマンドは実行しません。
- `この機体を監査` は明示操作時のみ既存 `tune-core::hygiene` を使い、正規化した hostname が台帳の一行にだけ一致するこの機体を読み取ります。共有設定が `true` または不正な型の機体は除外し、未記入は不明として表示します。遠隔監査は、機体ごとの権限と実際の接続先 hostname を確認できないため未対応で、SSH 接続もしません。会社管理の場合は操作者が適用ルールと権限を確認してください。監査には時間・件数の上限があり、失敗・打ち切り・未観測を表示します。指定された探索先がディレクトリと判定できない場合や一覧の読み取りに失敗した場合は探索未確認とし、例外本文や失敗した子のパスは追加しません。一方、子ディレクトリと `.git` の存在判定では OS エラーが非存在に畳まれる場合があり、全ての欠落は検出できません。読み取りが EOF に達していなければ途中出力を正常扱いしませんが、その後も reader スレッドが残る場合があり、全体の時間上限や子孫の回収は保証できません。監査の網羅性は不明です。Git の ahead / behind は最後の fetch 時点の追跡参照との差で、現在の remote とは限りません。fetch、リポジトリの変更、モデルの推論は行いません。
- ローカルの Strata `127.0.0.1:18080`、Ollama `127.0.0.1:11434`、LM Studio `127.0.0.1:1234` と、明示設定されたループバック先には、起動時と更新時にモデル一覧の GET だけを送ります。各応答には 2 秒・256 KiB の上限を設けています。サーバーに届かない場合は不明／タイムアウトであり、停止を断定しません。以前の成功と今回の失敗は別の時刻で示します。
- 追加先は、実行時の `FLEET_STUDIO_LLM_ENDPOINTS` に `表示名|IP:ポート|openai` または `表示名|IP:ポート|ollama` の形式で指定します。複数はセミコロンで区切り、先頭 8 件までを検査します。名前解決は行わず、ループバック・プライベートネットワーク・共有アドレス帯の IP のみ受け付けます。不正な指定と重複は区別して件数を表示します。設定は保存しません。
- 非ループバックの追加先は既定では「未照会」で、起動時や通常更新では接続しません。個別の「接続内容を確認」でアドレス・ポート・プロトコルと平文 HTTP であることを確認し、「この接続を有効化」した先だけ、この起動中にモデル一覧を取得します。許可は表示名を含む接続先の識別情報に結び付き、変更された設定には引き継ぎません。更新の受付時に確認中の内容を無効にし、更新待ちの間は新しい確認を始められません。「許可を取り消す」は更新待ちの間も利用でき、前回の値も直ちに消します。未開始の通信を阻止できたか、開始が確定して取り消せない場合があるかを表示します。未照会・失敗・古い結果は区別し、推論やモデルの変更は行いません。会社管理か個人かは推定しません。
- 追加先の確認・有効化・許可取消は現在マウス操作のみで、キーボードだけでの操作には対応していません。

`R` で保存データを再読込、`A` でこの機体の衛生監査、`/` または検索欄のクリックで表示範囲を検索します。読み込みや LLM 照会の途中に更新した場合は予約中と表示し、処理完了後に一度再実行します。元の読み込みが終わらなければ予約も待機します。検索中は矢印・Shift と矢印でカーソルや選択を移動し、Ctrl+A（macOS は Command+A）で全選択できます。検索は最大 256 バイトで、IME の変換中は Enter・Esc を一覧操作に使わず、一覧は確定前の条件のまま表示します。確定・終了後は一覧の矢印でリポジトリと最近の作業を選択でき、Enter は作業場所を優先し、なければ最初の確認済み PR を開きます。各作業行のボタンから PR を個別にも選べます。Windows で場所を表示すると、親フォルダを Explorer で開き対象を選択します。GitHub 以外の元情報は開けません。

貼り付けは未対応です。Ctrl+V（macOS は Command+V）ではその旨を表示し、クリップボードは読みません。IME 対応は実験段階です。Windows のサンプル画面では日本語 IME の基本的な変換・確定・取消を確認しました。フォーカス喪失、入力上限、絵文字・合字、押下から解放までに描画が変わる場合は Windows 実機で未検証です。macOS の動作も未検証です。双方向テキストの表示・クリック位置は保証していません。GPUI 0.2.2 の Windows 実装は入力 handler 未登録時の IME 位置問い合わせに解放漏れの可能性があり、アプリ側では登録中の位置不明を仮座標で扱いますが依存側のケースは未解決です。検索語をログや保存データに書き出しません。

ディレクトリはドライブを先に検査し、固定・リムーバブルドライブの既存ディレクトリだけを受け付けます。UNC やネットワークドライブ、構成要素にシンボリックリンクやジャンクションなどの reparse point を含むパスは拒否します。各要素の検査後に同時変更される競合は防げず、実体がネットワークでないことを完全には保証できません。macOS を含む他の OS ではリンク起動は未対応と表示します。

リンク起動は専用スレッドで行い、結果をスクロールに関係なく画面上部に表示します。5 秒を超えた場合は終了待ちとし、同じ操作の重複を防ぎます。OS への引き渡しは、ブラウザの接続やフォルダ画面の表示完了を保証しません。対象や OS エラーの本文はこの起動処理のログやエラー表示に含めません。

## 制約と次の候補

この画面は `fleet-status` を実行せず、Katala Tune が保存した分析と既存の衛生監査 API を利用します。保存済み構成図には非公開機の構成を含み得る一方、現状の API では機体・権限の対象を確認できないため、実データのリポジトリ構成は既定で DB から読み込まず、検索もできません。表示は未確認です。この機体の明示監査結果とサンプルは利用できます。将来、対象機体と scope を限定して権限を確認できる専用読み取り API が必要です。DB 読込が 5 秒を超えた場合は待機中と表示し、同じ読込を重複起動しません（元の処理を強制終了する保証はありません）。LLM の追加接続先は自動発見しません。常時監視、設定変更、再起動、任意コマンド実行、モデルのロード・推論は提供しません。

次は残る IME 操作の実機検証と、安全に待機時間を制限できる貼り付け、各機の現在の到達性、監査対象の個別選択、関連ドキュメント・Issue の紐付けを優先します。
