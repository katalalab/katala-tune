# 探索時の属性不明を保持する計画

> 実装は同じ担当者が `superpowers:executing-plans` に沿って進める。未確認の理由と実装方式はレビュー結果を踏まえて確定する。

**目的:** 探索中の属性判定に失敗しても、確認済みの結果を残し、確認できなかった範囲を固定の理由で伝える。

**対象:** `probes/repo_hygiene.py` の既定 root、子・`.git` の判定、発見後の linked 再確認と優先順位。必要な場合は JS／Rust の reason と表示も対応する。

**制約:** 任意の既定 root と `.git` の通常の不存在は従来どおり扱う。既知結果、上限による打ち切り、symbolic link と既存の Windows reparse 挙動を区別する。実データ・通信・子プロセス・Job・削除・cleanup を伴う試験は行わない。実 OS の通知順や junction の実証は合成試験から主張しない。

## 手順

- [ ] 実ソースの関数を仮想 filesystem・時刻・Git 出力につないだ純粋テストを追加し、4 種の属性失敗と上限時の並び替えを個別に失敗確認する。
- [ ] 通常の不存在、非ディレクトリ、アクセス可能な `.git` ファイル／ディレクトリ、既知行の保持、停止状態の区別を合成入力で確認する。
- [ ] reason と表示の互換性を確定後、最小限の修正を加え、同じ個別テストを再実行する。必要な JS／Rust の parity も副作用を監査して個別に確認する。
- [ ] 差分と機密情報の有無を確認し、レビューを依頼する。実環境での確認は未実施として扱う。
