# これからの Katala Tune

手元の機体を、軽く・速く・安定して見て手当てする1つの操作卓にする。単体で動く（SSH で調べ、手元の SQLite に保存し、承認制で操作する）ことを本体とし、常時監視（katala-fleet）や Do-gu は後から足す連携にする。

## 領域

| 領域 | 中身 | 状態 |
|---|---|---|
| 分析・最適化 | 機体ごとの所見・スコア・承認制の操作（許可リスト・確認・直前の再確認） | v0.3 で稼働 |
| 状態 | 正常／注意／異常／不明と根拠・継続時間、異常化と回復の通知 | v0.3 で稼働 |
| ログ | OS のログの取り込み・全文検索・同種ログの集計 | v0.3 で稼働 |
| 道具（MDM のソフト台帳） | 全機体の CLI・パッケージ・アプリと版、版の違い、追加・削除の履歴 | 裏側を実装（画面はこれから） |
| Do-gu | 棚卸しから作るデッキの下書き。全件を見せて承認したものだけ登録 | 裏側を実装（画面はこれから） |
| AI エージェントのログ | Claude Code・Codex のセッションの要約（期間・モデル・トークン・ツール呼び出し・失敗・PR）。本文は読まない | 設計 |
| SSH | `~/.ssh/config` の各ホストの到達性・認証方式（エージェント／鍵ファイル）・鍵の種類と古さ・known_hosts | 設計 |

## AI エージェントのログ（設計）

- 対象: `~/.claude/projects/**/*.jsonl`、`~/.codex/sessions/**/rollout-*.jsonl`。この機体だけで Codex 11GB・Claude 0.8GB あるので、**ファイルごとに読んだ位置（バイト）を覚えて差分だけ読む**
- 取り出すのはセッション単位の数値と名前だけ: 開始・終了、cwd（手元の DB にだけ保存）、モデル、版、ターン数、ツール呼び出し数と失敗数、トークン（入力・出力・キャッシュ）、フックのエラー、PR へのリンク。**会話の本文・ツールの入出力は読まない・保存しない**
- 画面: 機体×日ごとの使用量、失敗の多いツール、長いセッション、機体ごとの版のずれ（道具の棚卸しと同じ表の部品）

## SSH（設計）

- この機体の `~/.ssh/config`（`ssh -G <host>` で解決後の値）と、台帳の機体への到達性・所要時間
- 認証の経路（エージェント・鍵ファイル）、鍵の種類（ed25519 か）と作成日、known_hosts の食い違い
- 変更はしない（鍵の作成・配布・設定の書き換えはこのアプリでは行わない）

## 実装の言語（Rust 化）

1. **本体を Tauri 2 へ**: 裏側（調査の実行・保存・判定・自動スキャン・常駐・通知）を Rust に、画面は今の JS のまま。Electron（約 250MB・常駐メモリ大）から OS 内蔵の WebView に替えて軽くする。DB と台帳は同じ場所・同じ表を使うので、どちらの版でも同じデータを読める。Electron 版は同じことができるまで残す
2. **各機体での調査を Rust の単一バイナリへ**: Python・PowerShell の起動を無くして速くする。配布はアプリが SSH で置き、ハッシュを確かめてから実行する。読めるスクリプト（今の probes/）は予備として残す
3. 画面は JS（必要なら TypeScript）。Swift は Windows で SwiftUI が使えないため選ばない

## 守ること

- 調査は読み取り専用。変更する操作は許可リスト・確認ダイアログ・直前の再確認を通す（docs/safety.md）
- 外へ送るのは操作者が承認したときだけ（Do-gu の登録など）。秘密・本文・コマンドライン引数は集めない
- 依存は最小限。個人・環境の情報をリポジトリに書かない（`npm run oss-check`）
