# Official hardware source coverage

Revision 5 adds the [USB/audio source ledger](specs-usb-further.md), [PCI/network/codec source ledger](specs-windows-further.md) and [additional acquisition scope](specs-further-resolution.md). Manufacturer text, CAB/driver archives and official OS driver source files retain different material/coverage types. The source-file entries use fixed release versions and explicit line locations; they do not claim manufacturer verification of retail products. Microsoft-distributed manufacturer packages retain both publisher/distributor provenance and inner INF hashes. Link trust additionally permits official Windows Update download hosts, the exact Logitech/fw_updates and torvalds/linux release/commit paths, Plugable's documented S3 bucket path and kuroutoshikou.com; unrelated repositories or S3 buckets remain rejected.

Catalog revision 5 was reviewed on 2026-10-25. It contains 100 records: 34 product or product-family records and 66 manufacturer/OEM/official OS-driver hardware-ID/function mappings. This document lists public product identities and sources only; it contains no machine inventory or assignment of products to machines.

`models` contains explicit aliases matched case-insensitively after trimming. There is no substring, prefix, suffix, kit-name, or fuzzy matching. A match identifies the scope described by the source; it does not establish the installed configuration or enabled setting. Published maximum frequencies, transfer rates and endurance ratings are product specifications, not measurements. Every SSD performance field uses `up_to`; rated TBW is not remaining drive life.

Revision 3 also supports explicit `hardware_ids` with a section, four-digit hexadecimal vendor ID and device/product ID. These mappings have empty `models` arrays, so generic names cannot trigger a match. Their scope is the manufacturer-identified silicon family/function, separate from an exact product-model match. An ID mapping does not establish the motherboard SKU, stepping, board revision, enabled features or negotiated link.

## Full-body evidence

`source_evidence` contains the exact `url`, lowercase hexadecimal `sha256`, `coverage`, `verified_at` and concise `notes`. For raw HTML, `coverage: full_page` means the entire returned source page was saved and its relevant content read. When `material: rendered_dom_text` is present, the hash instead identifies the complete saved rendered body text for the stated page/tab state; it does not identify raw HTTP bytes or assert coverage of other support tabs. `material: pdf_document` with `coverage: full_document` identifies the original completely downloaded PDF bytes, with one-based PDF `pages` locating claims. `supporting_source_evidence` records independent sources and an explicit `claim_scope`; it does not silently promote claims outside that scope. No local machine path is included in public metadata.

## Link trust and maintenance

Manufacturer roots include `rme-audio.de` and `razer.com`, covering `archiv.rme-audio.de`, `rme-audio.de` and `mysupport.razer.com`. The completed flyer/manual retrieval additionally needs `micron.com` and `razerzone.com`, covering `assets.micron.com` and `dl.razerzone.com`. The additional public-ID sources require `tp-link.com` for `static.tp-link.com` and `logi.com` for `support.logi.com`. Existing manufacturer roots cover `crucial.com`, `sandisk.com`, `dell.com`, `eizoglobal.com`, `logitech.com`, `cdrdv2-public.intel.com`, `edc.intel.com`, `rog.asus.com` and `download.asrock.com`. Domains researched but not used for catalog records do not need link-trust expansion.

Future updates should preserve exact aliases, record the source scope, and distinguish a capability from a current setting. A changed part suffix requires evidence; it must not be accepted by stripping the suffix. Existing revision-1 records retain their sources and are not represented as newly revalidated by this expansion.
