# 軽量化とリリース整備の受入条件

1. 修復・リリース・道具/AI/ライブ表示の既存 PR を head ごとに独立レビューし、指摘を直す。
2. Rust + Tauri を標準の開発・配布経路に揃える。Electron は互換比較用に名前を分ける。
3. 版・公開情報・JS / Rust の検証と、macOS / Windows のアプリ本体のリンクを CI で確認する。
4. 署名つき Mac universal / Windows x64 配布物と更新 manifest を作り、版・署名・配布 URL を読み返す。
5. マージ済みで他の作業に使っていないブランチだけを整理する。dirty worktree や未統合の開発は残す。

機体の修復はログ同期・ホスト全体の状態・サービスの実効状態で判定する。負荷隔離中の機体をベンチマークで検証しない。実機の GUI と更新受入が未観測なら未検証として残し、CI の緑を代用にしない。
