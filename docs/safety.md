# 変更操作の安全設計

Katala Tune が機体に変更を加えるのは `lib/actions.js` の許可リストにある操作だけ。調査（probe）とログ収集は読み取り専用。

## NeonMonitor 1.1.x のレビューから取り入れたこと

NeonMonitor（Windows のメモリ監視・自動強制終了ツール）の静的解析レビューで、「自動でプロセスを終了する道具」が踏みやすい失敗が具体的に見つかった。同じ型の失敗をしないよう、プロセス終了を次のように作っている。

| NeonMonitor で見つかった型 | Katala Tune での対策 | 根拠（テスト） |
|---|---|---|
| モードを変えても、進行中のカウントダウンが古い判断のまま終了に進む | 判断（分析）と実行の間で状態が変わりうる前提で、実行の直前に機体側で条件を確かめ直す。確認ダイアログの後にもう一度台帳を読み直す | `test/actions.test.js` |
| 対象を決めてから終了するまでに、別のプロセスに入れ替わっていても気付かない | PID・プロセス名・起動時刻（macOS は `lstart`、Windows は `StartTime` を UTC で）の3つが一致しなければ中止（exit 3） | 同上。実機でも、名前違いを渡して中止することを3系統で確認 |
| 負荷が回復していても終了する | 直前に負荷を測り直し、1コアの `min_cpu`%（既定50）を下回っていれば中止（exit 4） | 同上 |
| 保護リストを読めないとき、内蔵の除外だけで対象を選んでしまう | 台帳（保護リストを含む）を実行の直前に読み直し、読めなければ実行しない。`plan()` は保護リストが渡されなければ拒否する | 同上「保護リストを読めないとき」 |
| 遅れた結果で「終了した」と断定する | 終了を指示した後、5秒以内に消えたことを確かめた場合だけ成功（exit 0）。確かめられなければ「終了未確認」（exit 5） | 同上 |
| 書き込み失敗を握りつぶす | 実行記録は SQLite のトランザクションで書く。失敗は画面に出し、成功扱いにしない | `test/logs.test.js` |

このほか:

- OS の中核・セキュリティ・AI エージェント・python/node などの実行環境は、終了を提案しない（`NO_KILL`）。台帳の `protect` で足せる。
- `shared: true` の機体（家族との共用機など）は提案だけで、実行ボタンを出さない。`plan()` も拒否する。
- 引数はすべて検証してからコマンドに埋める（PID は整数、名前は英数と一部記号、GUID・起動時刻は形式を固定）。PowerShell 本体にはシングルクォートを含めない（ssh 越しの Git Bash で包むため）。
- Windows の ssh 既定シェルが Git Bash の場合、`/setactive` のような引数がパスに書き換えられる。`powercfg -setactive` の形で渡す（実機で発見）。

## 実行記録（承認 → 実行 → 結果）

- 承認が無ければ実行器を呼ばない。承認の後にもう一度台帳を読み直し、接続先（alias・OS・この機体か）が変わっている・共用機や保護対象になっている・台帳を読めないときは実行せず、理由（「中止（実行していない）: …」）を実行記録に残す。
- 実行の直前に「未完了」の記録を書く（書けなければ実行しない）。実行が終わったら同じ記録に結果と戻し操作を書く。結果を書く前にアプリが止まった操作は、再起動後も「未完了」のままで、成功にも失敗にも数えない。戻す操作も出さない（状態が分からないものを戻さない）。
- probe の失敗は `reason`（timeout・unreachable・auth・error）と画面用の `reason_text` に分ける。元のエラー文は残す。
- 流れは `lib/runner.js`（Electron）と `Engine::confirm_and_run`（Rust）。どちらも子プロセスの実行口を差し替えられ、受入試験は偽の ssh と一時ディレクトリの偽の対象で行う（`test/acceptance-issue19.test.js`・`crates/tune-core/tests/acceptance_issue19.rs`、記録は `docs/acceptance/issue-19.md`）。

## 効果の確かめ方

変える前に計測し、変えた後に同じ計測をして、差が誤差の範囲なら元に戻す。電源プランを「高パフォーマンス」にする操作は、2台で 1スレッドの計測が -1.6%（誤差の範囲）だったので戻した（2026-10-03）。この結果は提案文にも書いてある。

## ライブ表示のサンプラー

- `probes/live_*` も読み取り専用。集めるのは数値と、上位プロセスの PID・実行ファイル名（macOS は .app の名前も）だけで、引数・環境変数・パスは出さない。
- 機体に常駐させない。画面が見ているあいだだけ動かし、合図が 2 分途切れたら止める。止めた後に機体に残らないよう、標準入力が閉じたら終わる・sshd のプロセスを見張る・15 分で自分から終わる、の 3 つを重ねている（docs/architecture.md。最初の 2 つは、ssh を止めても Windows 機にサンプラーが残った実機の失敗から足した）。

## ログの取り扱い

- 収集元は許可したものだけ: Windows の System（エラー以上と、ハードウェア・ドライバ・ディスク・メモリ枯渇の警告）、Application（エラー以上）、NeonMonitor の `guard.log`。macOS の DiagnosticReports（ファイル名と見出しだけ。スタック等の中身は読まない）と、カーネルのエラー。
- 1件は最大1,000文字。トークン・API キー・JWT・`password=` などは伏せてから保存する（`lib/logs.js` の `REDACT`）。
- 1回の取り込みは1か所あたり最大300行。macOS のカーネルと Windows の System・Application は、同じ形（数字・16進・パス・引用符の中身を伏せた鍵が同じ）の繰り返しを、**取り込む前（probe）に代表1行と実際の件数（`count`）へまとめてから**300行の上限を掛ける。繰り返しで枠が埋まって、ほかの異常が捨てられるのを防ぐため。代表行の本文は最初の1件のものだけで、繰り返しの本文は持ち出さない（伏せ字は代表行にそのまま掛かる）。まとめきれず上限を超えた分は、その行が持っていた件数で捨てた件数として記録し、画面の「取り込みの状態」に出す（溢れていることを隠さない）。詳細は docs/observability.md の 7。
- (機体, 取り込み元, uid) で一意なので、同じ範囲を読み直しても重複しない（代表行の uid は繰り返しの最初の1件のもの）。失敗したら次回やり直す。
- 保持は30日。同種ログの件数（指紋ごと）は残す。

## 道具の棚卸し

- 調査はインストール先を読むだけ（パッケージマネージャもネットワークも使わない）。macOS 付属のアプリ（実体が `/System` 配下）と OS 付属の CLI は数えない。
- 読めなかった取り方（権限・壊れたマニフェストなど）は `failed_sources` として返し、保存のときはその種類の前回の一覧を残す。失敗を「空」と見なして削除に記録しない。Windows の調査はエラーを止める設定（`$ErrorActionPreference = 'Stop'`）で書く。
- 機体の初回の棚卸しは増減を記録しない（`inventory_nodes` に初回を済ませた印を残す）。

## AI エージェントのセッション

- 調査（`probes/ai_sessions.py`）は `~/.claude/projects` と `~/.codex/sessions` の JSONL を読むだけ。機体には何も書かない（続きの位置は DB が覚えて、毎回スクリプトに埋め込んで渡す）。
- 取り出すのはセッション単位と時間ごとの数・名前・時刻・モデル・版・トークン・PR の URL と、重複集計を防ぐ応答・ツールの ID。会話の本文・ツールの入出力・コマンドライン引数は取り出さない・保存しない（`test/ai-sessions.test.js` で出力に含まれないことを確かめている）。
- cwd・ファイルの鍵・エラーの文のホームは `~` に置き換える（Claude Code のプロジェクト名に入っているホームも）。
- 1回は 25 秒で区切る。形の違う行は飛ばし、1行のせいでファイル全体を読めなくしない。読めなかったファイルは位置を進めず、次回に読み直す。
- Claude の応答は機体・ファイル・応答 ID ごとに各トークン項目の最大値を保存し、増えた分だけ集計する。ツール ID と名前を DB に保持するため、次の取り込みで届いた失敗も元の名前に結び付く。過去の ID 全量を毎回機体へ送らない。現在の取り込みのメタデータは全ファイル通算 4,096 件・512 KiB で区切り、未処理行の直前から次回再開する。単独で上限を超える行は欠測を明示して進む。
- 旧版のバイト位置だけの Claude データは、ID 台帳の構築と集計訂正のため一度だけ最初から読み直す（25 秒・メタデータ予算で区切る）。集計・時間別の量・ID 台帳・移行印・続きの位置を同じトランザクションで保存し、失敗時は全て戻す。
- 保存は tune-core の集計・時間別・続き位置と、Claude の応答（量・モデル・1 時間のキャッシュ書き）・ツールの ID の表（`ai_claude_messages` ほか）。台帳の機体に `"ai_sessions": false` と書くと、その機体からは取り込まず、残った続き位置を理由に短い間隔の空取り込みも続けない。**共用機（`shared: true`）は既定で取り込まない**（他の人のセッションの cwd や PR を集めないため）。取り込むときは `"ai_sessions": true` と明示する
- ファイルをまたぐ重複を除くため、応答（ID ごと）の量は元のファイルが消えても残す（履歴の量と重複除去が変わらないように）。ID は上と同じ不透明な文字列で、本文ではない
- 出どころの台帳（`ingest_run`・`source_span`）に残すのは、区間のバイト位置・区間の SHA-256・行数・調査スクリプトの版と SHA-256 だけ。本文は残さない。元ファイルとの照合も、機体で区間を読み直して指紋と行数だけを受け取る（読み取り専用）
- 連鎖のハッシュは行の書き換え・削除（末尾の削除は、別に持つ先頭・件数との突き合わせで）に気づくためのもので、先頭・件数も同じ DB にあるため、DB を丸ごと作り直せる相手には効かない（docs/observability.md）

## Codex の残り枠

- `probes/codex_limits.py` は各機体で `codex app-server` を起動して `account/rateLimits/read` を問い合わせ、窓の長さ・使用率・リセット時刻だけを出す。認証は Codex が持ち、Tune は Cookie・トークン・auth.json を読まない（`crates/tune-core/src/codex_limits.rs` のテストで、調査スクリプトが認証のファイルに触れないことを確かめている）。このスクリプト自身は機体に何も書かない（Codex が自分の認証を更新するなど、Codex 自身の動きはある）
- 呼ぶのは AI の取り込みのとき（既定 30 分ごと）だけ。**共用機では呼ばない**（`ai_sessions: true` と書いた共用機でも。呼ぶなら `"codex_limits": true`）
- テストは偽の codex（標準入出力で同じ受け答えをするスクリプト）で行い、本物の codex は呼ばない

## 外への送信（Do-gu）

- 送るのは操作者が画面で選び、確認ダイアログで承認したものだけ。ダイアログには全件と「公開ページに載る」ことを出す。
- 送る前に、下書き（除外を反映済み）にある slug だけを通す。確認の後にもう一度下書きを作り直して同じ検証をし、変わっていたら送らない（`lib/dogu.js` の `planPublish`・`samePlan`、テストあり）。
- 既にある道具への紐づけだけを送り、新しい道具は作らない。リトライしない。結果は実行記録に残す。
- Tauri 版の HTTP は OS の curl を使う（依存を増やさない）。API キーは引数に載せず、curl の設定を標準入力で渡す（他のプロセスから見えない）。https だけ・20 秒で打ち切る。テストは HTTP と確認ダイアログを偽物にして、POST の回数と中身を確かめる（`crates/tune-core/src/engine_tools.rs`）。

## ネットワークとセキュリティ

- 調査（`probes/mac_probe.py`・`win_probe.ps1` の netsec、`mac_logs.py`・`win_logons.ps1` のログイン）は読み取り専用。パケットの中身・コマンドライン引数・ファイルの中身は取らない。集めるのはプロセスの実行ファイル名・アドレス・ポート・防御の状態・自動起動の名前と実行ファイル名・ログインの日時と種別とアカウント名と送り元だけ。
- 通信の遮断・ファイアウォールの変更・自動起動の削除など、機体を変える処理は無い（所見の助言に手順を書くだけで、実行ボタンは出さない）。管理者権限は求めず、読めないものは「取れない」「権限が無い」と出す（Windows のセキュリティログは管理者か Event Log Readers のグループが要る）。
- 取れなかった部分は errors に理由を残し、空と見なさない（自動起動の一覧が取れなかった種類は削除として記録しない）。各取得に時間の上限があり、全体にも上限がある（macOS 15 秒・Windows 20 秒）。Windows は stdin だけを使う専用子プロセスから完了済みの部分を逐次受け取り、時間切れではその子だけを止めて残りを欠測にする。
- 宛先の IP と送り元は手元の DB にだけ置く。snapshot には残さず（件数だけ）、`net_peers` は 30 日見なければ消す。ログイン（送り元）はログと同じ 30 日。自動起動の増減の記録は 180 日。
- 台帳の機体に `"network": false` と書くと、その機体では netsec もログインの記録も集めない（調査スクリプトに `nonet`・`-NoNetwork` を渡す）。
- 共用機は、外向きの接続先（宛先）を既定で残さない。調査の結果を受け取った直後に宛先の一覧を落とし（`dropPeers`・`drop_peers`）、DB にも画面にも入れず、初めての接続先も覚えない。台帳の `"network_peers": true` で明示したときだけ残し、所見は提案だけにする
- 共用機は、ログインのアカウント名と送り元も既定で集めない。台帳の `"network_logins": true` で明示したときだけ集める。既定値へ戻した後は、以前の接続先とログインの送り元を最新結果・状態・ログ検索・署名・セキュリティ画面へ返さない
- 外向きの接続は分析のときの1回の標本。最初の 7 日は覚えるだけで、知らせない（学習の途中で全部が「初めて」になるのを避ける）。自分の待ち受けの番号で受けた接続（外から来た接続）は外向きに数えない（相手の番号が毎回変わり、誤検知になる）。
