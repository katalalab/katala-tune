# 電力・Clock

「全機を分析」の後、サイドバーの「電力・Clock」を開きます。全操作卓の私有台帳に同じ機体を登録すると、各操作卓から分析・対応する電源設定を操作できます。SSH は既存の接続設定を使います。

表示する値は取得元と範囲を区別します。

- NVIDIA GPU: 電力、UUID、上限と対応範囲、Graphics / SM / Memory Clock、温度、P-state。
- Windows CPU: LibreHardwareMonitor の package センサー、または標準 Energy Meter の RAPL package。Energy Meter の mW は W に換算し、core / DRAM の重複は加算しません。Clock は性能カウンターの推定値と基準値を分けます。
- Apple Silicon: 任意の既存 `macmon` または `~/.katala-tune/bin/macmon` から CPU / GPU / CPU+GPU+ANE の電力、E/PコアとGPU Clockを読みます。SMC のシステム電力は推定として別表示します。センサーがなければ未取得です。

入力側電力は、外部電力計の実測があればその値を使います。それ以外は CPU+GPU、またはそれらと重なる SoC 電力に「その他の電力」を加え、電源効率で割ります。その他の電力と効率は実測校正値を入力してください。未設定の機体をゼロ扱いして全機合計を出しません。5分を超えた分析結果も合計から除きます。

試算時間・単価・通貨を保存すると、表示時の電力が続く場合の kWh と費用を計算します。条件は各操作卓の私有DBに保存します。ライブ表示では直近最大300点を台形積分し、欠測・取得元・セッションの切替で区間を切り、観測秒数とカバー率を表示します。重なる観測窓は合算しません。

機体への変更は確認ダイアログ、台帳と現在値の再確認、対象側ロック、変更後の読戻し、操作記録を通します。共用機は分析だけです。GPU電力上限はUUIDと実機の対応範囲が必要です。Macの低電力モードやWindowsの電源プランには対象OSの権限が必要です。以前の固定Clock範囲を復元できない機体ではClock設定を無効にします。

読戻しに失敗した場合は成功と表示しません。別ツールが第三の値へ変更した場合は上書きせず、不確実な状態として記録します。復元にも現在値の確認が必要です。

CLIの `tune power` は保存済みの分析と計算条件を読み取り専用で返します。CLIから設定変更は実行できません。
