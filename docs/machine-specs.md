# 機体のスペック比較

Tauri版のサイドバー「スペック比較」から機体を選び、「仕様を収集」を押す。表は横スクロールでき、「差分のみ」と検索で絞り込める。取得元はセルのヒントと「公式情報・取得元」で確認する。JSONコピーには選択中の機体だけを含める。

## 収集方法

Rustの `tune specs-local` は台帳・DBを開かず、その機体の読取結果を `katala_specs.v1` JSONで返す。WindowsはOS内蔵のCIM（PowerShell経由）、限定したレジストリ読取と、導入済みの場合は `nvidia-smi` を使う。macOSは `system_profiler`、`sysctl`、`pmset`、`csrutil status`、`fdesetup status` を使う。Pythonや配置した調査スクリプトは使わない。追加ソフトウェアはインストールしない。

`tune specs [機体ID ...]` はローカルまたは既存SSH接続で収集し、私有DBに最新の成功結果と最終試行を保存する。引数省略時は稼働中の収集許可機が対象。画面では明示的に選択した機体のみを収集する。共用機は既定で除外し、台帳の `specs: true` による明示的な読取許可がある場合だけ対象になる。`shared` 自体や最適化の許可は変更しない。台帳の `specs: false`、退役・一時停止・対象外の機体は収集を拒否する。

`tune specs --saved [機体ID ...]` は収集せず保存済みの仕様・最終試行を表示する。既存DBを読取専用で開き、未作成なら欠測として返す。`tune specs --help`、`tune --version`、機械向けの `tune version --json`・`tune cli-info --json`、全機体の版照合 `tune versions` は [CLIの使い方](cli.md)を参照。

遠隔機の `~/.katala-tune/bin/tune`（Windowsは `tune.exe`）にも、この機能を含むRust CLIが必要。見つからなければPATH上のCLIを試す。古いCLIやSSHの失敗は画面で案内し、前回の成功結果を消さない。収集時にはバイナリの自動配布を行わない。通常のアプリ更新で同梱CLIも更新する。

収集は1回限りで、4機体ずつ処理する。遠隔機は1台120秒、WindowsのCIMは100秒、macOSの各providerは22秒、標準出力は2MiBを上限とする。セクションは最大256件。閲覧だけでは再収集せず、24時間以上前の結果と失敗後の前回値には要更新を表示する。

## 表示内容と限界

- 本体・CPU・メモリ・GPU・ストレージ・マザーボード・BIOS/ファームウェア・OS・ディスプレイ・NIC・USB・Thunderbolt/USB4・PCI・オーディオ・取得可能な電源/セキュリティ/仮想化設定。
- メモリは部品番号・スロット・容量・公称転送速度・設定転送速度を分離。容量のバイト数はGiBに換算する。Macの共有メモリを専用VRAMに換算しない。CPUクラスタはOSが報告する名前を表示し、Super/PerformanceをP/Eに推測変換しない。
- WindowsのCIM `AdapterRAM` は専用VRAMとして使用しない。NVIDIAはモデルが一意に照合できる場合のみドライバー報告を採用。同名GPUが複数ある場合、AMD/Intelの専用VRAM、未提供のドライバー/ファームウェア情報は未取得になる。
- セキュアブートの権限不足、OSが公開しないXMP/EXPO、MacのRecoveryポリシーなどは理由を表示する。標準APIに出ない電源ユニット・ケーブル・筐体・冷却部品やBIOSの全設定を推測しない。
- 「OSからの報告なし」「未取得」「未対応」「権限不足」を区別する。OSの仮想デバイスも含むため、デバイス数は物理部品の数ではない。最大クロックや公式仕様だけで性能順位を付けない。
- Windowsのストレージは一意なOSディスク番号で `MSFT_Disk` と関連付け、NVMe/SATA等のバス、セクター、パーティション方式、読み取り専用・起動属性を追加する。OSの `SCSI` 表記だけで物理接続方式を推測しない。VBS・Credential Guard・メモリ整合性は設定と実行状態を分ける。OSリリース版・UBR、NICのMTU・仮想/物理属性も表示する。
- Windowsの画面WMI取得失敗時は、最大64件の保存済みEDIDを検査し、チェックサムが正しい基本情報だけを表示する。これは過去の接続を含み、現在接続・有効状態は未確認。元のWMI失敗も残す。シリアル番号やEDID本体を保存しない。
- macOSは利用可能なUSB providerを選び、新しい `SPUSBHostDataType` にも対応。公開されたTRIM/SMART、Wi-Fiファームウェア、Thunderboltの物理ポート、音声のサンプルレート・入出力チャンネル、SIP・FileVaultを表示する。ポートの広告速度と実効転送速度は区別する。
- NICの送受信リンク速度は別々に保持し、同じ場合だけ共通速度も表示する。これはOSが報告するリンク属性で、仮想NICの値を含み、通信の実測性能を意味しない。未公開のMTU（0）は表示しない。Windowsの項目は [MSFT_NetAdapterの公式定義](https://learn.microsoft.com/en-us/previous-versions/windows/desktop/legacy/hh968170(v=vs.85)) に従う。

## 公式仕様

`data/specs-catalog.json` に確認日、完全一致する型番、メーカーの出典URL、適用範囲と公表仕様を持つ。カタログv3は33製品・ファミリーと29件のIntel PCI機能を登録する。[公式資料と照合範囲](specs-official-sources.md)に出典と未確定の型番を記録する。型番の完全一致は `matched`、区分付き公開ID表による機能・ファミリー確認は `identified` とし、別に集計する。基板SKUやstepping、設定値をIDから推測しない。未登録の型番・IDは「未照合」と明示する。

本文を取得して該当箇所を確認した資料は `source_access` と `source_evidence` にURL、取得本文SHA-256、確認範囲・箇所を記録し、画面にも表示する。HTMLページ全体の取得はそのページの本文を意味し、リンク先資料すべての取得ではない。索引抜粋や本文確認の記録がない項目は区別する。現在の本文確認はEIZO、RME、Intelの4本文を31カタログ記録で参照する。Crucialの5資料とRazerの資料には取得制約が残る。

OSが報告した構成と公式の選択肢・上限は別に表示する。インターネットへの機体情報送信や自動検索はしない。出典リンクが開けない環境では「URLをコピー」を使う。

各機体に公式照合・未照合・照合対象外・不足項目・取得制約の件数とCLI/カタログ版を表示する。不足項目は区分ごとに算出し、OS・設定・集約メモリ・仮想NICを物理製品の未照合数に含めない。OS・設定・ファームウェアに添える公式の説明資料は、実機の設定値や搭載ファームウェア版の照合を意味しない。文書参照とカタログ照合はSSH受信時にもローカルの信頼済み資料から再生成する。

「公式情報・不足項目の表示」で未取得・未照合のみ、本文確認の記録がない照合済み項目のみを絞り込める。Macのメモリ・音声の情報グループ、集約メモリ、仮想インターフェース、物理ポートを区別し、SSDコントローラーにディスク容量を要求しない。記録種別はSSH受信時にも取得元と公開フィールドから再構築する。

Windowsは一意のデバイスインスタンスIDを収集プロセス内部だけで関連付け、同名USB/PCI機器等のドライバー版・提供元・INF名・署名状態を補う。既存の確定値を上書きせず、曖昧な結合は行わない。インスタンスID全文は保存・送信しない。INFはファイル名のみ。`present` はOSの現在の検出状態であり、非検出は非搭載や削除を意味しない。署名値はOS報告で、ファイルや証明書の独立検証ではない。Macは実際に公開されたメモリ種別・メーカー、Wi-Fi規格/チャンネル、パネルの公開ID/リフレッシュレート、OSビルドと `sysctl hw.machine` のアーキテクチャも表示する。

## 私有データ

収集にはシリアル番号、UUID、MAC/IPアドレス、SSID、ユーザー名、ファイルパスのフィールドを含めない。Rustが許可したフィールドだけを正規化し、SSHから受信したJSONも再検証する。機体名・台帳・収集した実機JSONはリポジトリに置かない。既存のSQLite `meta` に `specsReport:<id>` / `specsAttempt:<id>` を保存し、旧版のDB構造を変更しない。

## 検証

`cargo test -p tune-core --test specs --test specs_coverage --test specs_macos_expansion --test specs_windows_expansion --locked`、`node --test test/specs.test.js`、`npm run check`。実機では `tune specs-local` と画面からの収集を確認する。Electron互換版ではRust版の利用案内を表示する。
