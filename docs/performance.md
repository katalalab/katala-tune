# 高速化の確認

ライブの通常の差分は時刻順に追加し、全体の再送・重複・順序が乱れた差分だけを従来どおり時刻でマージする。直近5分の保持期限と、同じ時刻の点を上書きする規則は変更しない。

ログの伏せ字と同種ログの指紋は、正規表現がマッチしなければ文字列全体をコピーしない。伏せ字の規則、UTF-16単位の上限、指紋の値は変更しない。

## 再測定

```sh
node scripts/benchmark-live.js
cargo run --release -p tune-core --example performance --locked
```

どちらも合成データだけを使い、台帳・SSH・実データベースを使わない。初期化後に7回測り中央値と最小値をJSONで返す。ビルドや他の重い処理を終えてから測る。

ライブは6台を毎秒更新する2万イベントで、通常版と同じ301点の保持を検査する。以前の `renderer/live.js` をファイルに保存した場合は、そのパスを `benchmark-live.js` の引数で渡せる。

ログは2万行の正規化を測る。伏せ字と指紋の正しさは `cargo test --workspace --locked` のJS一致テストで別に検査する。実際の取り込み時間には機体上での収集と通信も含まれるため、正規化の測定値を全機体の分析時間と扱わない。

## 検証

`test/live.test.js` は順序の乱れ・重複・全体の再送を含む1,000イベントについて従来のマージ結果と比較し、点のない状態イベントでも保持期限を守ることを検査する。画面はmacOSのTauri版で、ローカル分析・スコア表示・ライブ更新・画面移動時のサンプラー停止を確認する。

アプリ容量は配布用 `.app`、メモリは本体とWebViewのRSS合計として別々に測る。RSSは共有ページを重複計上し、台帳の機体数やDB内容、画面、OSのメモリ圧迫で変わるため、異なる環境の単発測定を一律の削減率として扱わない。
