# Native topology reader source stage

The native reader reads only an explicitly approved Windows checkout/file selection. It does not enumerate directories, open the application ledger/database, collect selected settings, or start PowerShell. The entire approved selection is atomic: errors return no capture, and non-null continuation cursors are rejected before IO.

`collect_with` accepts an original absolute deadline and injected readonly source/Git interfaces. Request policy and aggregate limits are checked before IO. Manifest paths are checkout-relative in both the allowlist and RawManifest; only the filesystem lookup combines root, checkout and manifest. A single bounded raw buffer must match the approved exact length and SHA before strict UTF-8 decoding. All checkouts use four fixed Git metadata operations; after all files are read, all HEADs are checked again, for at most five Git processes per checkout. Git commands expose fixed arguments and a complete environment through getters; the ambient environment is never copied.

The Windows adapter supports local NTFS only. It anchors once at a drive-root handle, then uses FILE_OPEN-only NtCreateFile calls with one validated component and a held RootDirectory. Every child denies write/delete sharing and rejects reparse points; held file identities are checked before and after reading. No descendant is reopened using an absolute path and there is no directory enumeration or separate hash reopen. This readonly source guard does not establish executable artifact identity or protect against a malicious OS.

This interface is source-stage capture, not an admission boundary. Injected implementations and the public RawCapture/ProcessReceipt types do not establish OS ownership, executable provenance, or execution authority. The standalone native entry requires an operator-approved Git artifact SHA in the exact native-v2 request body. It pins that executable once before any query, retains the same NTFS file/ancestor handles through all four metadata operations and every final HEAD check, and launches only the pinned volume-GUID path. Every suspended root must match the retained actual image before Resume; each query consumes its own opaque OS completion. There is no PATH or unknown-hash fallback. The missing-origin operation alone may admit exit one with empty stdout and stderr after all actual cleanup acknowledgements. Legacy-v1 requests omit the new field and reject any supplied value. The injectable UnsupportedGitRunner remains available for tests; it is not the real standalone runner. Ordinary remote collection remains disabled pending acceptance and integration gates.

The outer supervisor must own the Rust reader and every Git descendant and independently observe actual exit/code zero, EOF and Job cleanup. A processing acknowledgement must not substitute for that observation. The outer's own actual exit requires an external observer. Windows native acceptance, artifact identity binding, trusted finite policy, settings selectors and native continuation remain separate gates.

Existing Windows guard, framing, early CLI rejection and finite input/output tests remain required. PS/Electron compatibility paths are retained. Source fixtures do not prove Windows runtime or fleet acceptance.

## Finite standalone chain

All three Windows-only commands dispatch before application runtime, ledger or database initialization: `topology-native-reader`, `topology-supervise`, and `topology-verify`. The reader authenticates approved bytes and emits a native-v2 processing frame. It does not report its own exit. The supervisor owns the Rust reader and its Git descendants in a fresh Job and consumes an opaque OS completion only after actual root exit zero, all retained exits, Job empty, both EOFs and the writer completion. Its response binds the original raw body, canonical derived request frame, whole processing response frame, native identities and separately expected artifact hash. The independent verify entry owns and observes the supervisor and its descendants, consumes its own real completion, then validates the supervised frame and returns capture bytes. Wire codecs cannot construct either local capability.

Each observer retains its own original absolute deadline. A child's shorter relative CLI budget is a local cap and cannot extend its parent's OS observation/admission deadline. The supervising request is derived by changing only nonce and budget, with exact canonical bytes and separate original-body/frame hashes. The native acceptance verifier performs the same explicit derivation for its supervised attempt; its final output is capture data, not a serialized witness. Blocking input and output are independently bounded by the standalone main thread's self-only termination boundary. Failed/unknown cleanup releases no capture or witness.

Executable pinning supports local NTFS: single-component parent-handle-relative opens, no reparse traversal, retained ancestors/leaf without write/delete sharing, bounded same-handle SHA-256, volume-GUID-only launch, suspended actual image native-name equality plus held chain/file IDs before Resume. Image-name text is used with the immutable retained chain; it is not a standalone file-ID proof. A matching hash does not grant permission. The expected whole-helper hash and the Git SHA placed in the native request must come from operator-approved artifact records, never the child response or an unapproved discovery result. GUID launch availability, writable mappings, rename/reparse races, Unicode/case and actual nested child cleanup require native Windows measurement. DLL dependencies and every failure/cancellation lifetime are not claimed pinned. Unconfirmed cancellation has capability zero.

Legacy-v1 PowerShell framing remains separate. Its dedicated early entry uses the strict diagnostic Windows backend with a complete OS-derived environment and only fixed inbox module imports. Its PS-root diagnostic receipt is never relabeled as native Rust processing completion or an outer exit witness. Existing generic collector behavior and Electron compatibility are preserved.

Native continuation cursors, settings selectors, WSL/Posix native execution and ordinary remote activation remain unsupported in this stage. A whole approved selection must fit the finite caps or fail atomically; a legacy continuation cursor is rejected before IO. Root-owned deployment, real fleet acceptance and formal merge are separate from fixture/CI results.

The source-file path is anchored through retained checkout handles. Git metadata uses the approved DOS checkout spelling to preserve existing Git-directory hash semantics; changing the drive alias itself is outside this stage's stable local-drive assumption. Its metadata path is not a handle/GUID binding. A hostile OS/drive-namespace model and dependency DLL attestation are not claimed solved.
